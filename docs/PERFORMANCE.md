# 帧率、加速与测量

## 四种不同的量

- **渲染 FPS**：应用真实渲染帧的完成计数速率。
- **含合成 FPS**：应用交给呈现路径的帧计数速率，包含生成帧；它仍不是面板实际亮起次数。
- **显示 FPS**：后端可取得有效呈现时间戳时，据此估计实际呈现速率；当前不具备统一跨设备保证。
- **屏幕刷新率 Hz**：显示屏刷新节奏。屏幕可以重复上一张图，所以刷新率与新画面数量不必相等。

左下角有有效呈现统计时标注“显示”，否则标注“渲染”。开启超帧时增加“含合成”一行，含义是提交速率，不把它宣传为真实显示 FPS。面板和导出保留分开的指标；实际呈现不可用时使用空值/不可用状态，不伪造 120。

约每半秒记录 FPS，包含暂停、卡住、加速状态。应用内 CSV 与外部工具的时间窗口、计数层级可能不同，先对齐口径再比较，不能强制数字一致。

## 实际高刷新率

标准版目标 60。Pro / Pro Max 通过窗口和 Native VSync 的官方接口请求高刷新率并按当前时隙提交，目标 120。请求不等于系统一定批准；还受设备显示模式、功耗温度和实际帧时限制。

## 厂商加速

- XEngine：当前接入空间超分，降低内部像素工作量后重建输出。未宣称接入 AI 超分或 VRS。
- Graphics Accelerate Kit：当前接入帧生成，使用历史/当前画面和深度、相机信息生成中间画面，真实模拟不插值回写。
- 分别保留开关、状态和失败回退。编译含接入代码也不代表设备能力已激活。
- 当前未接入 ABR；不是所有讨论过的 Kit 都已经实现。

## 可重复的对比

使用 Release 构建；保持预设完整初值、模拟进度、视角、亮度、画质、窗口尺寸、分辨率与开关一致。记录设备/系统/应用版本、电量、温度和工具采样窗口。分别看线程、GPU 工作、等待和送显；总 CPU 使用率低并不能排除串行瓶颈。

不要把第三方芯片/系统的性能优劣写进 README：没有可复现同条件数据就没有比较结论。任何帧率提升都应有设备和场景条件，不能承诺固定百分比。
